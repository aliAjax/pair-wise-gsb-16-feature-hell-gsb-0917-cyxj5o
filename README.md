# hxwl-01 听力验配记录

门店听力师的验配档案与听力曲线工作台，支持 **录入 → 规则校验 → 签发冻结 → 复调修订** 的完整签发闭环，数据本地落盘，刷新不丢。

## 技术栈

React + Vite + TypeScript + CSS（localStorage 持久化，无后端依赖）

## 本地运行

```bash
npm install
npm run dev
```

开发端口：5101

## 签发阻断规则

每份记录包含左右耳分频气导（250/500/1k/2k/4k/8kHz）、骨导（500/1k/2k/4kHz）、
言语识别率、增益，以及转诊建议与调试反馈。

**以下任一情况不得签发：**

1. 缺少必填项（客户、分类、型号、听力师、全部听阈、言语识别率、增益）；
2. 数值超出合理范围（听阈 −10~120 dB HL、识别率 0–100%、增益 0–60 dB）；
3. 同频骨导高于气导（数据方向错误）；
4. 任一同频气骨导差 **> 20 dB** 但未填写转诊建议（恰好 20 dB 不要求）。

## 签发与修订

- 草稿编辑自动落盘；签发前实时列出全部阻断项，「签发并冻结」按钮在校验未过时禁用；
- 签发时深拷贝当前值作为冻结快照，`signedAt / signedBy` 一并落盘；之后写入、删除一律拒绝；
- 复调只能以已签发版本为蓝本，新建「第 N 次复调修订」草稿，旧版在版本链中只读保留；
- 已删除草稿带墓碑，防止其他标签页的旧数据把它“复活”。

## 筛选、统计与列表

- 状态（草稿/已签发）、分类、气骨导差 > 20dB、关键词筛选；
- 统计栏（已签发/草稿数、平均 PTA、平均言语识别率、阻断/待转诊数）与列表均由记录集合派生，
  随签发、修订、删除实时同步；
- 筛选条件和当前选中版本同样持久化，刷新后恢复。

## 冲突策略（多标签页）

监听 `storage` 事件做合并：**已签发历史永远优先**（冻结快照不被任何来源覆盖），
草稿按 `updatedAt` 取较新，墓碑只对草稿生效（不影响已签发记录）。

## 数据位置

- 记录仓库：`localStorage["hxwl-01.fitting-store.v1"]`
- 界面偏好：`localStorage["hxwl-01.fitting-ui.v1"]`

首次打开自动注入 3 条客户档案（含一条完整修订链，以及一条因缺转诊建议被阻断的复调草稿）作为示例。
